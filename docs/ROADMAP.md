## 二、 M1（真正 MVP 闭环）原子任务清单

每个任务遵循 **原子化（Atomic）** 与 **可验证验收标准（Acceptance Criteria）** 原则：

### 阶段一：波次怪潮刷新器 (WaveManager) —— 优先级 P0

- [ ] **Task 1.1：创建 WaveManager 基础类与波次数据结构**
  - **内容**：编写 `scripts/wave_manager.gd`，支持配置 3 个波次的怪群列表与刷新坐标。
  - **验收标准**：调用 `start_wave(1)` 时，能在竞技场四周平滑生成 Wave 1 的指定怪物。
- [ ] **Task 1.2：敌人存活动态统计与波次清场检测**
  - **内容**：监听所有已生成敌人的 `tree_exited` 或死亡信号，维护存活敌人计数器。
  - **验收标准**：当本波最后一个怪物倒地后，向外抛出 `all_enemies_cleared` 全局信号。
- [ ] **Task 1.3：波次 HUD 与剩余怪物指示**
  - **内容**：在竞技场顶部新增当前波次指示器（如 `WAVE 1 / 3`）及存活怪物数显示。
  - **验收标准**：击杀怪物时，HUD 剩余怪物数即时减 1，体验清晰。

---

### 阶段二：肉鸽三选一神力强化系统 (BoonSystem) —— 优先级 P0

- [ ] **Task 2.1：构建神力词条数据池 (BoonPool)**
  - **内容**：编写 `scripts/boon_system.gd`，实现涵盖三大极境的 6 大核心词条及效果注入方法。
  - **验收标准**：调用 `get_random_boons(3)` 能返回 3 个不重复的合法强化词条对象。
- [ ] **Task 2.2：搭建三选一卡牌 UI 场景 (BoonCardSelect.tscn)**
  - **内容**：创建全屏半透明遮罩面板，横向排列 3 张神话风格卡牌（金边古希腊青铜风）。
  - **验收标准**：卡牌清晰展示称号、流派标签、效果文本，鼠标悬停时微放大并亮起金边。
- [ ] **Task 2.3：抽卡流程与主角能力实时强化 (Player Upgrade Hooks)**
  - **内容**：波次结束触发弹窗并暂停游戏；玩家点击卡牌后，将效果应用到 Player（如缩短冷却、瞬步附加斩击判定），随后恢复游戏时间。
  - **验收标准**：选择【神行裂隙】后，下一波瞬步穿过敌人能够直观看到伤害数字并削减小怪 HP。

---

### 阶段三：局内流程控制器与胜负循环 (GameFlow) —— 优先级 P1

- [ ] **Task 3.1：全局胜负仲裁器 (GameFlowController)**
  - **内容**：在 Main 场景中集成完整状态机（`START -> BATTLE -> UPGRADE -> VICTORY / DEFEAT`）。
  - **验收标准**：正常打通 Wave 3 触发胜利逻辑；中途主角 HP 耗尽触发战败逻辑。
- [ ] **Task 3.2：战败界面与一键重开 (DefeatScreen.tscn)**
  - **内容**：主角死亡时呼出暗黑沉沦风格面板，显示存活波次与杀敌数，包含【向死而生（重新开始）】按钮。
  - **验收标准**：点击按钮能快速重置场景与状态，无残留 Bug。
- [ ] **Task 3.3：通关胜利界面 (VictoryScreen.tscn)**
  - **内容**：通关第 3 波后，呼出金色神话史诗面板，展示玩家本局的肉鸽神力流派搭配清单与通关耗时。
  - **验收标准**：界面具有成就感，提供【再次挑战】循环入口。

---
