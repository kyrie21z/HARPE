# 角色未弹反时小怪误触发弹飞与受创物理击退机制修复

## 问题与动机

- 玩家反馈：“近战小怪攻击角色, 角色不弹反, 小怪一样会被弹出去”。
- 根因分析：
  1. **ParryBox 默认常态可被检测（`monitorable = true`）**：
     Godot 中 `Area2D.monitorable` 默认为 `true`。原 `Player.tscn` 中 `ParryBox` 仅显式关闭了 `monitoring = false`，但未关闭 `monitorable`。
  2. **`_on_attack_hitbox_area_entered` 缺少招架激活状态校验**：
     在 `EnemyMelee.gd` 中，攻击判定框只要检测到 `area.name == "ParryBox"`，就直接判定为招架成功（`attack_was_parried = true`）并调用 `get_parried()` 将小怪暴力震飞 650 px/s！即使玩家完全处于常态（`State.NORMAL`）没有按右键，小怪扑击触碰到身前的 `ParryBox` 也会被当场震飞！
  3. **小怪命中反冲过度补偿**：
     前次修改在 `_on_attack_hitbox_body_entered` 中给小怪添加了 `bounce_dir * 220.0` 的反作用力击退，导致小怪抓中玩家后也会产生向后倒退弹跳。

## 尝试与条件

1. **ParryBox 严密生命周期管理**：
   - 在 `Player.tscn` 中显式设置 `ParryBox.monitorable = false`。
   - 在 `Player._ready()` 中默认将 `ParryBox.monitoring` 与 `ParryBox.monitorable` 均置为 `false`。
   - 仅在 `Player._execute_parry()` 激活瞬间将二者置为 `true`，0.15s 判定窗口结束后立刻通过 `set_deferred` 置回 `false`。
2. **EnemyMelee 攻击碰撞严密状态门禁**：
   - 在 `_on_attack_hitbox_area_entered` 中增加双重门禁：不仅检查 `area.name == "ParryBox"`，必须通过 `player.is_parrying_active()` 确认玩家此时此刻确实处于招架有效窗口内。
   - 在 `_on_attack_hitbox_body_entered` 中，未招架命中玩家时，小怪自身**绝对零击退**（`knockback_velocity = Vector2.ZERO`），仅将扑击速度归零（`velocity = Vector2.ZERO`）并原地执行攻击后摇。
3. **主角受创击退与运动模式保障**：
   - 玩家受创受到 380 px/s 后退击退，自然拉开 30~45px 身位，解除物理重叠。
   - 双方均为 `MOTION_MODE_FLOATING`，即使近身肉搏也不会发生卡壳锁死。

## 观察与证据

| 测试场景 | 修复前表现 | 修复后实测表现 | 判定依据 |
|---|---|---|---|
| 角色常态站立/走动，小怪正面扑击 | 小怪触碰 ParryBox 直接被当场震飞 650px/s | 角色受创扣 20HP 并后退，小怪**原地止步零后退** | `test_failed_parry_knockback.gd` 用例 2, 3 |
| 角色精准右键举盾招架 | 招架大成功，怪物瘫痪震退，神雷降下 | 招架大成功，怪物瘫痪震退，神雷降下 | `test_parry_damage_immunity.gd` |
| 扑击命中后小怪身位 | 小怪向后弹飞 220px/s | 小怪停留在扑击终点（坐标不变），仅角色被击退 | 坐标与速度零漂移断言通过 |
| 瞬步脱困响应 | 正常 | 瞬步瞬时清空击退速度 | 零操作迟滞 |

## 解释与经验

- 防御判定区域（如 `ParryBox`、`CounterBox`）在未激活时必须同时关闭 `monitoring` 与 `monitorable`，不可让攻击发起方的探测框在非防御帧提前侦测到。
- 探测回调中绝不能仅凭进入物体的名称（`area.name`）就草率判定机制成功，必须严格核验受击目标对象的内部运行状态（`target.is_active()`）。
