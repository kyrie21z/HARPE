# 精准手柄键位重构 (弹反B/攻击X/瞬步A)、神力选定交互与死亡/胜利结算面板手柄重开支持

## 问题与动机

1. **手柄键位调整**：
   - 弹反从 RB 调整绑定回 **B 键**（`JOY_BUTTON_B` = 1，与鼠标右键并存）。
   - 攻击保持为 **X 键**（`JOY_BUTTON_X` = 2，与鼠标左键并存）。
   - 瞬步保持为 **A 键**（`JOY_BUTTON_A` = 0，与 Shift / Space 并存）。

2. **死亡或通关大捷界面无法用手柄选择重新开始**：
   - **根因**：
     - 当游戏胜利（`_show_victory`）或玩家死亡（`_on_player_died`）时，结算面板变为可见（`visible = true`），但没有任何代码对面板上的重开按钮 `RestartBtn` 执行聚焦（`grab_focus()`）。
     - 由于初始焦点为 `null`，即便按下手柄 A 键，引擎也不会派发 `ui_accept` 给按钮，导致玩家在结算时无法用手柄重开。

3. **神力三选一交互精简**：
   - 用户明确要求选择神力界面仅支持摇杆/十字键左右切换高亮浏览（带高亮缩放光效），按下 A 键选定。彻底移除 X/Y/B 快捷键。
   - 修复第二关及后续关卡中因旧卡牌延迟删除导致的焦点树污染 Bug。

## 尝试与条件

1. **InputMap 与词条提示精准调整**：
   - `project.godot` 中将 `parry` 重新绑定为 `JOY_BUTTON_B`（1）与鼠标右键，移除 RB 与其他冗余按键。
   - `boon_data.gd` 中将雅典娜弹反与跨流派联动键位徽章更新为 `[ B / 右键 ] 镜盾` 与 `[ B ➔ X / 右键 ➔ 左键 ]`。
   - HUD 悬浮操作指引同步更新为 `• WASD / 左摇杆: 移动 | A / Shift: 瞬步 \n • X / 左键: 轻击/重斩 | B / 右键: 镜盾弹反`。

2. **重开按钮专用组件 `RestartButton`（`scripts/restart_button.gd`）**：
   - 设置 `process_mode = PROCESS_MODE_ALWAYS`，确保在游戏暂停状态下无障碍接收事件。
   - 监听 `visibility_changed`，一旦所属面板显示在屏幕树上（`is_visible_in_tree()`），立即 `call_deferred("grab_focus")` 主动抢占焦点。
   - 支持聚焦弹性放大（1.05 倍）视觉动效。
   - 在 `_input(event)` 中，捕获 `JOY_BUTTON_A`、`ui_accept`、Enter、Space，直接发射 `pressed` 信号并消费事件，双保险确保即刻触发 `_restart_game()`。
   - 在 `Main.tscn` 中将 `VictoryPanel` 与 `DefeatPanel` 下的 `RestartBtn` 挂载此脚本，文案明确标注：`✦ [ A / 点击 ] 再次挑战 (新一轮循环) ✦` 与 `✦ [ A / 点击 ] 向死而生 (重铸利刃) ✦`。

3. **神力三选一交互与跨房间持久修复**：
   - `BoonSelectUI` 维护内部 `focused_card_index`，通过左摇杆（带 0.5 阈值与 0.25 回中防抖）与十字键左右循环切换。
   - 选定严格由 `JOY_BUTTON_A` 与 `ui_accept` 触发。
   - `_render_cards()` 清场旧卡牌时显式调用 `cards_container.remove_child(child)` 立即断开父子关系，杜绝延迟队列污染焦点树。

## 观察与证据

- **自动化单元与集成测试结果**：
  - 运行 `test_gamepad_controls.gd`：
    1. InputMap 键位绑定：弹反->B、攻击->X、瞬步->A、确认->A 全部通过。
    2. 玩家手柄模式自适应与中立瞬步朝向校验通过。
    3. 第一关神力摇杆左右切换与按下 A 键选定通过。
    4. 第二关/后续关卡卡牌数量精准为 3，十字键与 A 键表现稳健通过。
    5. 第三关反向循环回环选定通过。
    6. 死亡界面与大捷通关界面手柄 A 键重开通过！
  - 全套回归测试通过（`test_boon_clarity.gd`、`test_failed_parry_knockback.gd`、`test_parry_damage_immunity.gd`、`test_chamber_transitions.gd`、`test_door_entry_integration.gd`、`test_enemy_hit_stun.gd`）。

## 解释与经验

- 结算界面的手柄交互体验关键在于“可见即聚焦（Focus on Show）”和“双保险输入拦截（Direct A-button intercept in _input）”。
- 配合专用的 `RestartButton` 节点级脚本，既不侵入场景核心架构，又能提供独立自包含的手柄响应能力。

## 关联与后续修正

- 修正了 `REC-20260927-04` 与 `REC-20260927-05` 早先版本中的 RB 弹反绑定，正式落地 B 键弹反。
