# 招架弹反免伤互斥与神雷判定竞态修复

## 问题与动机

- 玩家反馈：在实机游玩中，成功触发雅典娜神雷（全屏落雷降下且怪物被震晕），但角色依然扣除了 20 点生命值。
- 根因分析：
  1. **信号调度竞态**：怪物的攻击碰撞框（`AttackHitbox`）与玩家的身体碰撞体（`CharacterBody2D`）以及招架感应框（`ParryBox`）在同帧重叠。Godot 在物理帧内分发 `body_entered` 与 `area_entered`，导致扣血与弹反在同一瞬间先后执行。
  2. **受创后幽灵弹反**：怪物攻击前摇结束后判定生效持续 0.16s。若玩家慢半拍被命中扣血，因攻击框仍在 `monitoring`，随后几毫秒玩家按下的招架判定仍会接触该攻击框，导致“先扣血、后落雷”的荒谬体验。
  4. **弹反震退几何向量缺陷与击退抹除**：原 `get_parried()` 以 `ParryBox` 判定框作为击退原点，当怪物身位越过神盾时，向量计算反向指向玩家怀中；且神雷判定调用 `take_damage(40, Vector2.ZERO)` 时将原有 500px/s 击退重置为 0，导致被弹反怪物原地黏附在玩家身上。

## 尝试与条件

- 在 `Player.gd` 中新增 `parry_invincible_timer`（0.35s 绝对无敌保护期），招架大成功后立即激活。
- 在 `Player.take_damage()` 中增加正面招架拦截救赎：若受击瞬间玩家处于有效举盾招架窗口（正面约 210 度夹角），强制转为招架成功，绝不扣血并调用 `_parry_stun_nearby_enemies()`。
- 修正弹反击退物理逻辑（`EnemyMelee.gd`）：
  - 击退原点严格锁定为玩家身体中心（`player.global_position`），若角度反向强制朝面朝前方震飞。
  - 击退初速度提升至 650px/s（阻尼 1200px/s²，滑行位移 ~175px），瞬间拉开安全身位。
  - `take_damage` 增加保护：严禁 `Vector2.ZERO` 抹除已生效的弹反击退速度。
- 瞬步穿透体验优化：`Player._start_dash` 期间临时关闭与怪物身躯的碰撞（Layer 3 mask），实现 Hades 式自由贯通穿梭。
- 在 `EnemyMelee.gd` 与 `Bullet.gd` 中确立**互斥状态标记**（`attack_has_hit` 与 `attack_was_parried`）。

## 解释与经验

- 动作游戏中的防御/弹反判定必须具备**最高裁决优先级（Absolute Priority）**与**排他互斥（Mutex）**。
- 击退位移必须以防守者本体中心向外发散，严禁依赖偏移判定框导致向心吸附。
- 单次攻击行为（Swing/Slash/Projectile）必须遵守“要么击中、要么被招架”的生命周期约束，单次判定生效后必须立刻原子性关闭判定。
