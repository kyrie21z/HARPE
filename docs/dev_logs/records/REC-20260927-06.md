# 冲刺攻击判定与伤害全面修复，以及神力祝福卡牌描述极简一句话重构

## 问题与动机

1. **冲刺攻击伤害消失**：
   - 玩家反馈在瞬步中按下攻击键进行冲刺斩时，经常对身旁或前方怪物无法造成任何伤害。
   - **根因分析**：
     - 在先前的纯瞬身零碰撞改造中，纯瞬身关闭了 `dash_hitbox.monitoring = false`；而在触发冲刺斩 `_trigger_dash_strike()` 时，仅开启了弧形刀光 `hitbox.monitoring = true`，并未开启身位环形检测 `dash_hitbox`。
     - 同时，旧逻辑仅在 `_on_dash_hitbox_area_entered` 中判定伤害，且前置了 `if has_dash_damage:`，导致若未拾取赫尔墨斯祝福，基础冲刺斩（30 伤害）被完全吞掉。
     - 另外，Godot 4 在角色以 780 像素/秒高速冲刺或已贴身怪物时，动态开启 `monitoring = true` 并不会必定即刻派发 `area_entered` 信号，存在帧丢失现象。
     - 输入缓冲方面：玩家在挥刀后摇或蓄力中瞬步，或者在瞬步刚按下帧未精确同帧按下攻击时，`is_action_just_pressed("attack")` 极易错失。

2. **神力祝福描述过重**：
   - 卡牌界面此前包含副标题、多条词条说明、连击技巧小贴士等，视觉杂乱且文字过多，严重影响战斗节奏与选技决策。
   - 用户明确提出："祝福描述还是太复杂, 只能用一句话"。

3. **结算重开按 A 报错**：
   - 在胜利/失败界面按下 A 键后，出现报错 `RestartButton._input: Cannot call method 'set_input_as_handled' on a null value`。
   - 原因是调用重开逻辑时立即执行了重载，导致后续对视口输入状态操作空指针。

## 尝试与条件

1. **冲刺攻击判定双保险机制（`player.gd`）**：
   - **输入宽容与连续判定**：
     - 在进入瞬步时检测当前是否有攻击输入（`just_pressed`、`is_action_pressed` 或非蓄力攻击状态），瞬步过程中若按下攻击键亦能无缝衔接冲刺斩。
   - **双重碰撞区激活**：
     - 冲刺斩触发时同时开启前方扇形 `hitbox` 与周身 `dash_hitbox`（36px 半径）。
     - 显式调用 `_check_dash_strike_overlaps()`，使用 `get_overlapping_areas()` 实现 0 帧即时重叠检测，弥补高速位移下 `area_entered` 延迟的问题。
   - **单次冲刺斩去重结算**：
     - 维护 `struck_enemies_this_dash` 数组，统一通过 `_apply_dash_strike_hit(enemy)` 结算命中：
       - 基础造成 30 点伤害、320 击退力度与 0.3 秒受击硬直。
       - 若持有赫尔墨斯神力（`has_dash_damage`），伤害提升至 50 点，击退提升至 420，硬直提升至 0.4 秒。
       - 触发打击停顿（Hit-stop 0.05s）与镜头震屏（2.5px）。
   - **纯瞬身零伤害保持**：纯瞬身不按攻击键时，两组 hitbox 严格保持 `monitoring = false`，穿怪 0 伤害。

2. **祝福卡牌描述极简一句话重构（`boon_data.gd` & `boon_select_ui.gd`）**：
   - 在 `BoonData` 中为 6 项核心祝福定义专属 `one_sentence_desc`，严格收敛为单句纯数值与机制说明：
     - **Hermes 疾风之翼**：`"冲刺斩伤害提升至 50 点，且瞬步冷却大幅缩短 40%。"`
     - **Hermes 幻影迷踪**：`"瞬步在原地留下嘲讽石雕吸引怪物并吸收一次攻击。"`
     - **Athena 天威之怒**：`"成功弹反时降下天威神雷，对全屏所有敌人造成 40 点伤害并击晕。"`
     - **Athena 镜盾反冲**：`"弹反的魔矢自动锁定最近敌人弱点自导反击，造成 2.5 倍暴击伤害。"`
     - **Ares 泰坦巨力**：`"破灭重斩蓄力时间减半，且重斩伤害大幅提升至 100 点。"`
     - **Ares/Athena 破军战吼**：`"成功弹反后重置瞬步，且下一次攻击免蓄力直接轰出 70 伤破灭重斩。"`
   - 重构 `BoonSelectUI` 布局：
     - 彻底移除副标题、多条说明列表与提示信息面板。
     - 卡牌呈现结构：`[流派按键徽章] -> 神力名称 (24px 加粗) -> 分割线 -> 极简单句描述 (16px 居中) -> 底部选择提示`。

3. **重开按钮安全输入消费（`restart_button.gd`）**：
   - 在触发 `pressed` 信号与 `reload_current_scene()` 之前，先执行 `get_viewport().set_input_as_handled()` 消费输入，并使用 `call_deferred` 延迟重启，彻底消除报错。

## 观察与证据

- **全套自动化单元与集成测试结果**：
  - 运行 `test_failed_parry_knockback.gd`：
    - 验证 4：直接瞬身穿透敌人零伤害通过。
    - 验证 5：主动冲刺斩（Dash-Strike）有效削减怪物 HP（100 -> 70，扣除 30 点伤害）顺利通过！
  - 运行 `test_boon_clarity.gd`：
    - 验证 1：所有 6 个核心祝福单句描述完整性校验通过，字符无换行断裂。
    - 验证 2：BoonSelectUI 卡牌单句展示渲染与选定逻辑通过。
    - 验证 3：玩家注入神力状态正常。
  - 运行 `test_gamepad_controls.gd`：手柄键位（弹反 B / 攻击 X / 瞬步 A / 确认 A）以及结算重开全流程通过。

## 解释与经验

- 在高速动作游戏中，依赖单一物理帧的 `area_entered` 容易受到物理解算与位移跨步影响，结合 `get_overlapping_areas()` 的主动查询能极大保证攻击手感与打击判定判定一致性。
- 肉鸽游戏在选技高频交互场景中，信息的“认知负荷”越低越好。一句话直指数值加成与机制转变，比分段文学性描述更利于玩家在战斗间隙快速做出战略决策。
