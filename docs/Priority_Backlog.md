# 《HARPE》功能优先级表 (Priority_Backlog.md)

> **归属课程**：腾讯游戏学堂《AI游戏进化论》EP.04《用AI拆解功能与规划开发》  
> **核心原则**：**按依赖关系与价值密度严格分级（P0~P3）。P0 未全部验收通过前，严禁开发 P1 及后续任务！**

---

## 一、 优先级定义与准入准出标准

| 级别 | 定义与价值定位 | 交付原则 |
| :---: | :--- | :--- |
| **P0** | **必须具备（Must Have）**：决定产品是否成立的生死骨架。缺少任何一个，MVP 流程均无法运转。 | **最高优先级**，本阶段攻坚焦点，必须 100% 验收通过。 |
| **P1** | **应该具备（Should Have）**：核心游戏体验与信息反馈支柱，直接影响玩家手感与沉浸感。 | P0 验收通过后立刻实施。 |
| **P2** | **可以具备（Could Have）**：锦上添花项，如额外的音效增强、数值微调、更多词条拓展。 | 时间允许时迭代推进。 |
| **P3** | **坚决延后（Won't Have Now）**：当前阶段的绝对红线，杜绝新手“画大饼”，留到 M2/M3 里程碑。 | **严禁在 MVP 编码阶段动工**。 |

### ⚪ P3：延后项（MVP 坚决不碰的红线）

| 模块 | 功能名称 | 排除理由与后续归宿 |
| :--- | :--- | :--- |

| **平台** | **Steam 成就与排行榜接入** | 属于发布期打磨（EP.12~EP.13），阶段一严格杜绝。 |
