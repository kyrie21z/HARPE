# 《HARPE》MVP 范围声明文档 (MVP_Scope.md)

> **归属课程**：腾讯游戏学堂《AI游戏进化论》EP.04《用AI拆解功能与规划开发》  
> **核心原则**：**严格控制项目边界，防范新手范围蔓延（Scope Creep），用最小代价验证可玩产品闭环。**

---

## 一、 MVP 做什么 (IN SCOPE)

MVP 的唯一目标是：**交付一个让玩家在 3~5 分钟内完整体验“刀盾博弈”与“肉鸽构筑”的最小可玩产品闭环。**

### 1. 核心角色控制 (Player)
- **8 方向移动**：基于 WASD 的《哈迪斯》近战朝向风格（移动对齐，告别侧移太空步）；
- **神行瞬步 (Dash)**：Shift 键触发，顺应移动方向疾冲，带无敌帧与青蓝神行残影；
- **右手神兵 Harpe**：
  - 点按轻击：快速出刀垫步（Lunge），青蓝半月弧光；
  - 长按蓄力：压低重心蓄势，刀身泛起金芒，释放大范围破灭重斩并触发屏幕微震；
- **左手青铜镜盾 (Parry)**：右键 0.15 秒毫秒级弹反，小盾前推，镜面迸发神光。

### 2. 对抗与环境 (Arena & Enemies)
- **单一封闭竞技场**：带有边界碰撞阻挡和 4 根掩体石柱的矩形竞技场，相机平滑追踪；
- **2 种基础原型敌人**：
  - **近战狂暴怪**：索敌追逐，近身时 0.38 秒红光前摇蓄势扑击（专为诱发近战弹反设计）；
  - **远程石化祭司**：中远距离拉扯走位，周期性发射魔法飞弹（专为诱发镜面折射反弹设计）；
- **3 个递进梯度波次 (Waves)**：
  - Wave 1（试炼）：2 只近战狂暴怪；
  - Wave 2（夹击）：1 只近战狂暴怪 + 2 只远程祭司；
  - Wave 3（决战）：2 只强化狂暴怪 + 2 只远程祭司。

### 3. 核心手感三要素 (Juiciness / Game Feel)
- **打铁顿帧 (Hit-stop)**：攻击命中 0.06s 定格，完美盾反 0.15s 强力定格（基于真实时钟）；
- **屏幕微震 (Screen Shake)**：重斩 6px 震屏，盾反 9px 震屏，受击 5px 震屏；
- **受力与状态反馈**：怪物受击闪白、击退位移、盾反破势瘫痪 1.4 秒（泛黄瘫软且承受 1.8 倍易伤）。

### 4. 肉鸽核心三选一构筑 (Boon / Roguelite Upgrade)
- 每清空一波敌人，游戏暂停，弹出 3 张神力强化卡牌；
- **首发 6 大核心词条池**：
  - 【神行裂隙】：瞬步冷却 -40%，瞬步穿透造成 35 点斩击伤害；
  - 【金羽幻象】：瞬步留下嘲讽幻影自爆；
  - 【雅典娜的雷暴】：完美弹反在全场降下金光神雷（40 点 AOE 伤害）；
  - 【波光追踪】：镜面折射的子弹获得 100% 暴击与自动寻敌追踪；
  - 【泰坦破军】：破灭重斩蓄力时间缩短 50%，伤害提升 40%；
  - 【刚体反击】：完美弹反后下一次蓄力重斩瞬间免蓄力瞬发。

### 5. 局内生命周期结算 (Game Loop)
- **血量与状态**：主角 100 点生命值，UI 实时血条；
- **战败结算**：主角 HP 归零，弹出战败面板，支持【向死而生（一键重开）】；
- **胜利结算**：突破第 3 波敌人，弹出弑神初成胜利面板，展示流派组合并支持【再次挑战】。

## 二、 MVP 坚决不做什么 (OUT OF SCOPE)

为了杜绝半途而废，在 MVP 阶段**严禁在代码中开发以下功能**：

| 排除项 | 原因与处理原则 |
| :--- | :--- |
| ❌ **地牢随机生成与多房间拼接** | 耗时巨大且不影响核心手感验证，MVP 统一使用单一竞技场 |
| ❌ **高精度美术原画与逐帧骨骼动画** | 严格坚持程序化几何体（Polygon2D）白模，手感验证通过后再贴皮 |
| ❌ **局外持久天赋树与暗号升级** | 属于 Meta-Progression，留在完整版或阶段二 |
| ❌ **装备背包与局内商店买卖** | 肉鸽核心只需三选一，无需复杂的货币与商店交互 |
| ❌ **剧情对话树与 NPC 交互系统** | 背景故事作为沉浸底色，MVP 阶段不实现长文本对话系统 |
| ❌ **美杜莎 Boss 复杂多阶段大招** | 美杜莎作为独立里程碑 M2 打造，MVP 以第 3 波高潮精英战为终点 |

## 三、 范围防守承诺 (Scope Guardrail)

1. **不可临时加料**：开发过程中凡产生“加个武器换装”、“加个冲刺小游戏”等新想法，必须一律记入 `Priority_Backlog.md` 的 P3 延后区，严禁擅自编写代码；
2. **单一事实标准**：一切关于“该功能是否属于当前开发内容”的争议，以此文档为最终裁定依据。
