# 游戏开发留痕 (GameDev Trace)

本技能按项目安装在 `.agents/skills/`，作用于所属项目；保留项目专属规则与适配，不创建用户级全局安装。

将独立游戏开发经历保存为单一正文，区分客观事实（引擎表现/帧率/输入响应）、主观体验（手感评价/玩家反馈）、架构决策和执行授权；保留负结果及废弃方案，使未来检索能够回答“为什么这么做、做了什么、效果如何、为什么废弃某方案”。

## 选择工作范围

先检查目标项目的 AGENTS.md、现有归档规则和相关记录；已有规则优先复用，不另建平行账本。

- 用户要求在项目建立机制：执行“接入项目”。
- 用户要求记录或修正开发事件：执行“记录与收尾”；缺少机制时按当前授权创建最小记录结构，不顺带修改项目级代理规则。
- 用户只要复盘：优先使用并列的 weekly/阶段复盘模板；未安装时使用本技能的精简复盘模板。
- 用户只要模板：交付所需 assets，不将模板占位内容发布为真实记录。

## 接入项目

1. 盘点已有 records、索引、计划入口，优先适配已有结构；默认使用 `docs/dev_logs/`。
2. 读取 [规则模板](assets/PROVENANCE.md)，写入目标项目 `docs/dev_logs/PROVENANCE.md`，并建立 `records/`、`templates/` 和用于复盘的 `weekly/`。
3. 将 [记录模板](assets/templates/record.md) 和 [复盘模板](assets/templates/retrospective.md) 放入目标项目 `docs/dev_logs/templates/`。
4. 将 [AGENTS片段](assets/AGENTS.fragment.md) 合并到目标项目的 `AGENTS.md`，保留已有规则并避免重复；按实际目录调整所有引用。
5. 检查目录、链接、规则冲突及已有文件未被覆盖，报告实际创建或修改的路径。

本技能不含自动发布脚本；采用手工审阅与发布，不宣称启用了自动留痕或遗漏检测。

## 记录与收尾

1. 按问题检索目标项目 records 中的已有经验、避坑记录与适用条件；已有开发只读当前规范和必要记录。
2. 遵循目标项目 PROVENANCE；使用 [记录模板](assets/templates/record.md) 起草。
3. 记录正/负/未定结果、重要失败/Bug/穿模、核心机制与假设变化、放弃方向及废弃代码；纯格式整理不新增记录。
4. 为关键参数注明引擎版本、参数数值、测试场景、来源位置和核验等级；事件日期与写入日期分开，未知动机如实注明。
5. 发布前核对来源位置与代码指纹（SHA-256），核对关键参数与实际工程一致；检查关系ID确实存在。
6. 检查ID未占用后保存 `docs/dev_logs/records/<ID>.md`。
7. 同ID同正文视为幂等，异内容使用新ID与 corrects/supersedes 关系追加，保留旧记录及负结果。

收尾报告记录ID、路径和实际检查；无实质开发决策变化用 `NO_DEV_DELTA` 加原因，失败用 `ARCHIVE_PENDING` 加原因及草稿位置。

## 简明复盘

使用 [复盘模板](assets/templates/retrospective.md)：Hypothesis/目标一句话，Design每点一句话，Result用最小充分对比表格，Conclusion每点一句话，并链接源记录。
